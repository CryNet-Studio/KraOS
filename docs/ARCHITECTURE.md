# ArkOS 0.1.0 实现结构

ArkOS 使用 C11 与 x86 汇编实现，是由 GRUB 加载的 freestanding x86_64 内核。桌面、终端和文件操作均直接运行在 ring 0，没有 Linux 内核、宿主操作系统 API 或浏览器运行时参与内核执行。

当前设计优先保证一条完整、可验证的路径：从 ISO 启动，初始化虚拟硬件，接收输入，绘制桌面，并在 RAM 中操作文本文件。它还没有形成支持用户态程序的通用操作系统。

## 引导与地址空间

`grub-mkrescue` 将 `build/kernel.elf` 与 GRUB 打包进 ISO，同时包含 BIOS 与 x86_64 UEFI 启动入口。内核文件是 **ELF64**，通过 **Multiboot2** 协议进入 `boot/entry.S` 的 32 位保护模式入口。

启动代码验证 CPU 长模式能力，建立 GDT 和页表，启用 PAE 与长模式，再调用 C 入口 `kernel_main()`。内核链接在物理地址 1 MiB，使用静态 128 KiB 启动栈。页表以 2 MiB 大页恒等映射前 4 GiB 地址空间。

这份映射仅用于内核原型运行，不提供进程隔离或有效的内存保护边界。系统没有页框分配器、堆分配器、按需分页、独立进程地址空间或用户态。UI 缓冲区、事件队列和文件表都是静态分配的固定容量数组。

内核运行后不再调用 BIOS 或 UEFI 服务。`platform.c` 校验 Multiboot2 标签边界、内存映射条目和帧缓冲布局。屏幕必须是位于前 4 GiB 地址范围内的 32 位 RGB 帧缓冲；桌面接受 800 × 600 至 1920 × 1200，默认请求 1024 × 768。

## 模块接口

| 模块 | 职责 | 主要约束 |
| --- | --- | --- |
| `boot/entry.S` | 32 位入口、长模式和静态页表 | x86_64 CPU，Multiboot2 |
| `kernel/interrupts.S` | 中断入口、保存寄存器、恢复执行现场 | 遵循 System V AMD64 C 调用约定 |
| `kernel/platform.c` | 硬件初始化与事件产生 | QEMU PC、8259 PIC、PIT、i8042、COM1、CMOS |
| `kernel/desktop.c` | 主循环、窗口、应用界面和图像输出 | 单个前台事件循环，CPU 软件绘制 |
| `kernel/shell.c` | 内置命令和输出记录 | 不执行外部程序，不实现脚本解释器 |
| `kernel/vfs.c` | RAM 文本文件表 | 24 个文件，每个最多 4095 字节 |
| `kernel/lib.c` | 内存、字符串与数字转换函数 | 不依赖宿主 libc |

共用类型和函数声明位于 `include/ark.h`。所有模块静态链接进同一个内核，GUI 应用之间没有地址空间或权限边界。

## 中断、事件与主循环

平台将 8259 PIC 的 IRQ 映射到中断向量 32～47，只开放 PIT、键盘、PIC 级联和鼠标所需的中断。PIT 以约 100 Hz 运行，为 uptime、界面时钟刷新和光标闪烁提供节拍。

汇编中断桩保存通用寄存器，规范化异常错误码，清除方向标志并对齐栈，然后调用 C 处理函数。内核使用 `-mno-red-zone -mgeneral-regs-only` 等选项编译，避免普通用户态 ABI 假设与中断执行冲突。

PS/2 驱动将键盘和鼠标输入转换为 `Event`，写入固定 256 槽事件环。前台读取时短暂关闭中断，溢出时丢弃最旧事件。桌面主循环消费事件、修改应用状态，并在需要时重新绘制。空闲路径检查队列后使用 `sti; hlt` 等待中断，避免遗漏已经排队的输入。

这不是多任务调度器：窗口切换只改变 UI 焦点和绘制顺序，没有创建或切换用户进程。

## 显示与输入

GRUB 提供线性帧缓冲信息，ArkOS 自行绘制壁纸、窗口、文字、按钮和鼠标指针。画面先绘制到静态内存画布，再按帧缓冲 pitch 和 RGB 通道位置复制到显示内存；没有 GPU 命令提交、硬件加速或独立窗口服务。

字体为捆绑的 8 × 16 ASCII 位图；`scripts/generate_font.py` 可从 DejaVu Sans Mono 重新生成。字库没有汉字，非 ASCII 字符不会被正确显示。

键盘使用 i8042 翻译后的 set-1 扫描码和美式布局，解码 Shift、Caps Lock、功能键和常用控制键。鼠标使用三字节 PS/2 相对协议，没有滚轮或绝对指针。USB 键鼠、xHCI 和 VirtIO 输入均未实现。

桌面维护五个固定应用窗口，支持拖动、最大化／还原、隐藏、关闭和重新打开。Terminal 的输入框最多保存 95 个 ASCII 字符；终端输出保留最多 128 条内部行记录，每条最多 99 个可见字符，显示时再按窗口宽度折行。

Notes 持有当前文件的文本副本，每次追加字符、换行或退格后写回 RAM 文件表。编辑点固定在末尾，没有光标移动、选择、撤销或剪贴板。Files 中的路径文字是显示标签，底层只有一个平面目录。

## Shell 与 RAM 文件系统

`shell_execute()` 仅分派固定命令，没有任意代码执行、ELF 程序装载、管道、重定向或子进程。解析器有独立的 511 字节上限；当前 GUI 输入框的 95 字符限制更小。`shell_print()` 同时输出到串口和有界的屏幕行缓存，满载时移除最旧行。

`open` 命令通过 `shell_action` 通知桌面打开 Files、Notes、Settings 或 About，而不是启动新进程。`reboot` 和 `shutdown` 调用平台专用入口。

`vfs_files` 是 24 个 `VFile` 组成的静态数组。每个槽包含占用状态、最长 39 字符的文件名、4096 字节缓冲区和内容长度；其中一字节保留给字符串结束符，因此文本上限为 4095 字节。名称区分大小写，只允许英文字母、数字、点、下划线与连字符。

创建、查找、覆盖与删除都检查边界。创建同名文件返回已有槽位，不清空内容；超长写入在修改文件前被拒绝。每次启动重新初始化文件表并加入三个示例文件。没有块设备、磁盘格式、日志、权限模型或持久存储。

## 时钟、诊断与电源

RTC 读取 CMOS 的稳定快照，并处理 BCD／二进制与 12／24 小时格式。当前接口只返回时、分、秒，Shell 的 `date` 不提供年月日。默认 QEMU 配置使用 UTC；系统没有时区数据库、NTP 或设置时钟的界面。

`mem` 和 About 显示 Multiboot2 内存映射中 type-1 可用区域的总量，不是实时剩余内存。COM1 以 115200 波特率输出启动信息、Shell 输出和致命异常；异常日志包含 RIP、错误码，页故障还包含 CR2。

重启优先请求 i8042 复位，并以 triple fault 作为后备。关机写入 QEMU PC 的 ACPI PM 控制端口及旧的 Bochs 兼容端口。这是针对测试虚拟硬件的电源控制，不是通用 ACPI 实现。

## 构建和验证

构建使用 GCC／GNU binutils 的 freestanding x86_64 目标，禁用 PIE、栈保护器、red zone 等依赖运行环境的默认机制。链接器不引入宿主 libc。`grub-file` 验证最终 ELF 具有 Multiboot2 头，GRUB 和 xorriso 负责生成启动 ISO。

`tests/boot_test.py` 在 QEMU TCG 中通过 QMP 注入真实的 PS/2 输入，检查串口反馈并保存屏幕转储。验证范围包括 BIOS／OVMF UEFI 启动、命令与文件操作、Notes 编辑、应用切换、鼠标交互、重启后的 RAM 重置和关机。该测试不是 USB、真实磁盘、物理硬件或通用固件兼容性验证。

另对 Shell 与 VFS 使用临时宿主测试桩进行过边界与随机输入检查，包括文件数、39／40 字符名称、4095／4096 字节内容、行缓存滚动和 4000 条随机命令；AddressSanitizer 与 UndefinedBehaviorSanitizer 检查通过。宿主检查不替代真实内核启动测试。

## 建议的后续开发顺序

1. **内存基础设施**：从引导内存映射构建页框分配器，保留内核与帧缓冲区域，再加入受控堆分配与更严格的页权限。
2. **持久存储**：先在虚拟机中实现一种明确的块设备驱动，再添加文件系统、错误处理和显式保存语义。
3. **用户态与隔离**：建立用户态入口、系统调用和独立地址空间，再实现任务调度及可执行文件装载。
4. **桌面编辑能力**：增加 UTF-8 与中文字库、编辑光标、选择、撤销、命令历史和更完整的输入处理。
5. **硬件扩展**：在已有回归测试上逐项加入 PCI 枚举、ACPI、USB／xHCI、网络与音频，不将 QEMU 专用路径当作通用驱动。

上述项目均为后续计划，当前版本未实现。
